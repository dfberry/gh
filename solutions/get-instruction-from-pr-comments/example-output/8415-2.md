## TERMINOLOGY REQUIREMENTS

### Use "file share" as two words consistently [HIGH]
The term "file share" should always be written as two separate words, not as "fileshare".
- ✅ CORRECT: "file share"
- ❌ WRONG: "fileshare"

### Avoid using "managed" as a noun or resource name [HIGH]
Do not use the term "managed" as part of the resource name or to describe the service name. Use "managed" only as a descriptor for the serverless nature or service characteristics, not as a proper noun.
- ✅ CORRECT: "Create a new Azure file share with the Microsoft.FileShares resource provider. This creates a high performance, fully managed file share accessible via the NFS protocol."
- ❌ WRONG: "Create a new Azure managed file share resource."

## SERVICE-SPECIFIC DISTINCTIONS

### Name availability check scope is resource group, not location or global [HIGH]
The "check name availability" operation for file shares requires the resource group context because file share names do not need to be globally or regionally unique. They must be unique within the resource group.
- ✅ CORRECT: "Check if the file share name 'projectdata' is available in resource group 'rg-prod'."
- ❌ WRONG: "Check if the file share name 'projectdata' is available in location 'eastus'."

### File shares are accessible via NFS protocol and provide high-performance storage [MEDIUM]
When describing Azure File Shares, emphasize that they are accessible via the NFS protocol and provide high-performance, fully managed storage for applications and workloads.
- ✅ CORRECT: "File shares provide high-performance, fully managed storage accessible via the NFS protocol."
- ❌ WRONG: "File shares provide basic storage accessible via SMB only."

## NAMING CONVENTIONS

### Example resource group and file share names [MEDIUM]
Use realistic example names for file shares and resource groups in prompts:
- Resource groups: "rg-prod", "rg-backup", "rg-dev", "rg-archive", "rg-media"
- File shares: "project-data", "backupshare", "userdocs", "archive2024", "mediafiles"

Example prompt:
- "Create a new file share named 'project-data' in resource group 'rg-prod' at location 'eastus'"

## PARAMETER USAGE

### Required parameters for file share operations [HIGH]
- **Resource group**: Always required for create, delete, update, and snapshot operations.
- **Name**: Required for operations targeting a specific file share.
- **Location**: Required for create and limit/recommendation queries.
- Optional parameters include mount name, media tier, redundancy, protocol, provisioned storage size, IOPS, throughput, public network access, NFS root squash, allowed subnets, and tags.

### Location parameter refers to Azure region [HIGH]
When specifying location, use Azure region names such as "eastus", "westeurope", "centralus", "eastus2", "westus".
- ✅ CORRECT: "Get file share limits in location 'eastus'"
- ❌ WRONG: "Get file share limits in resource group 'rg-prod'"

## PROMPT STRUCTURE GUIDELINES

### Preferred prompt patterns for Azure File Shares

**For creating a file share:**
- "Create a new file share named '{file-share-name}' in resource group '{resource-group-name}' at location '{location}'"
- "I need to create a file share called '{file-share-name}' in resource group '{resource-group-name}' at location '{location}'"
- "Set up a file share '{file-share-name}' in resource group '{resource-group-name}' at location '{location}'"

**For checking name availability:**
- "Check if the file share name '{file-share-name}' is available in resource group '{resource-group-name}'"
- "Can you verify whether '{file-share-name}' can be used as a file share name in resource group '{resource-group-name}'?"

**For snapshot operations:**
- "Create a snapshot named '{snapshot-name}' for file share '{file-share-name}' in resource group '{resource-group-name}'"
- "Delete snapshot '{snapshot-name}' from file share '{file-share-name}' in resource group '{resource-group-name}'"

**For getting or updating file shares:**
- "Show me all file shares in storage account '{storage-account-name}'"
- "Update the file share named '{file-share-name}' in resource group '{resource-group-name}' to modify its quota"
