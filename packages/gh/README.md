# gh (gh-sdk)

This package provides a small GitHub SDK used in the monorepo.

## Prettier

Prettier is installed and configured as an independent formatting tool (not tied
into ESLint).

Available scripts (run from repository root):

- npm --prefix npm_packages/gh run prettier:check # check formatting
- npm --prefix npm_packages/gh run prettier:format # apply formatting

Note: The existing `format` script still runs ESLint --fix. Prettier is
intentionally separate so teams can use it independently of ESLint
configuration.

## Usage examples

Below are simple examples showing how to use the SDK to search and list
repositories. All functions are exported from the package entrypoint.

1. Search repositories with filters

```ts
import { searchRepos } from './src/repos.js';

const res = await searchRepos({
  q: 'test',
  language: 'TypeScript',
  stars: '>100',
  per_page: 10,
  token: process.env.GH_TOKEN, // optional, increases rate limits and visibility
});

console.log(
  res.total_count,
  res.items.map((r) => r.full_name),
);
```

2. List user repositories (single page)

```ts
import { listUserRepos } from './src/repos.js';

const repos = await listUserRepos('octocat', { per_page: 50, page: 1 });
console.log(repos.length, repos[0]?.full_name);
```

3. Paginated listing (inspect Link header)

```ts
import { listOrgReposPaginated } from './src/repos.js';

const page1 = await listOrgReposPaginated('my-org', {
  per_page: 50,
  page: 1,
  token: process.env.GH_TOKEN,
});
console.log(page1.items.length, page1.hasNext, page1.nextPage);

if (page1.hasNext) {
  const page2 = await listOrgReposPaginated('my-org', {
    per_page: 50,
    page: page1.nextPage,
    token: process.env.GH_TOKEN,
  });
  console.log('page2', page2.items.length);
}
```

4. Auto-paginate and filter by language

```ts
import { listUserReposByLanguage } from './src/repos.js';

const tsRepos = await listUserReposByLanguage('octocat', 'TypeScript', {
  per_page: 100,
  maxPages: 10,
});
console.log('TypeScript repos:', tsRepos.length);
```

5. Search by topic

```ts
import { searchReposByTopic } from './src/repos.js';

const cliRepos = await searchReposByTopic('cli', {
  per_page: 20,
  token: process.env.GH_TOKEN,
});
console.log(cliRepos.total_count, cliRepos.items.length);
```

Notes:

- Use `token` when calling endpoints that require authentication or when you
  want higher rate limits.
- For large result sets prefer the paginated helpers or `listAll*` convenience
  functions which fetch multiple pages.
- All API calls use `fetch` under the hood and return parsed JSON types
  described in TypeScript types.

## CLI examples

These repository-focused examples are provided as small Node scripts in
`./examples` and a helper in `./scripts` that uses the GitHub CLI to create an
`examples/.env` file containing `GH_TOKEN`.

Create/refresh an env file containing `GH_TOKEN` (uses local `gh` CLI,
interactive login if needed):

```bash
cd npm_packages/gh
node ./scripts/gh-prepare-and-run.mjs
```

Preview stale repos (dry-run; reads `examples/.env` by default):

```bash
node ./examples/archive-stale-repos.mjs --env-file=examples/.env
```

You can explicitly request a dry run even if `--yes` was passed by using
`--dry-run`.

Machine-readable output:

The scripts support `--output=json` to emit a JSON listing suitable for
automation. Example:

```bash
# list stale repos as JSON
node ./examples/archive-stale-repos.mjs --env-file=examples/.env --output=json > stale.json

# categorize repos (light checks uses GraphQL batching; full checks fetch README per-repo)
node ./scripts/categorize-repos.mjs --input=stale.json --fetch --checks=light --output=json > results/categorized.json
node ./scripts/categorize-repos.mjs --input=stale.json --fetch --checks=full --output=json > results/categorized-full.json
```

## TypeScript scripts and generated output

The indexer was converted to TypeScript and now compiles into `dist/scripts`.
Generated outputs are written to a `generated` directory by default. You can
override the output directory with the `--out-dir=PATH` flag to the indexer or
by setting the `GENERATED_DIR` environment variable.

Build the scripts and run the full index+categorize pipeline:

```bash
cd npm_packages/gh
# compile scripts
npm run build:scripts
# run the compiled indexer (writes to ../../generated by default)
node ./dist/scripts/index-all-repos.js
```

Or run the npm helper which builds then runs the compiled script:

```bash
cd npm_packages/gh
npm run examples:categorize-all -- --out-dir=/path/to/generated
```

Run the categorizer against an existing generated repo list (respects
`GENERATED_DIR`):

```bash
export GENERATED_DIR=/path/to/generated
cd npm_packages/gh
npm run examples:categorize-gen
```

Clean generated outputs:

```bash
cd npm_packages/gh
npm run examples:clean-generated
```

Archive stale repos (will prompt for confirmation; `--yes` enables the PATCH
requests):

```bash
node ./examples/archive-stale-repos.mjs --env-file=examples/.env --yes
# then type: yes
```

Change staleness threshold (days):

```bash
# show repos not updated in the last 2 years (730 days)
node ./examples/archive-stale-repos.mjs --env-file=examples/.env --older-than-days=730
```

Save results for review or pipe to a pager:

```bash
node ./examples/archive-stale-repos.mjs --env-file=examples/.env > stale-repos.txt
node ./examples/archive-stale-repos.mjs --env-file=examples/.env | less
```

Notes:

- The token must grant appropriate repository scopes to archive repositories
  (repo scope for private repos or public repo scope for public repos).
- All examples default to dry-run unless `--yes` is passed.
- If you want non-interactive runs, suggest using
  `printf 'yes\n' | node ... --yes` or I can add a `--force` flag to skip the
  final prompt.

- Use `--dry-run` to force non-destructive behavior even if `--yes` is supplied.
- Use `--output=json` to emit machine-readable output (JSON).

Delete zero-size repos:

You can delete repositories that match the filter and have zero size by using
`--delete-empty` (alias `--delete-zero-size`). For safety the script requires
`--yes` and will prompt you to type `delete` unless you also pass `--force`.

```bash
# delete zero-size stale repos (requires confirmation)
node ./examples/archive-stale-repos.mjs --env-file=examples/.env --yes --delete-empty

# force deletion non-interactively (use with care)
node ./examples/archive-stale-repos.mjs --env-file=examples/.env --yes --delete-empty --force
```

Delete all zero-size repos (all owned repos regardless of staleness):

```bash
# dry-run: list all owned zero-size repos
node ./examples/delete-zero-size-repos.mjs --env-file=examples/.env

# actually delete zero-size repos (requires confirmation or --force)
node ./examples/delete-zero-size-repos.mjs --env-file=examples/.env --yes
node ./examples/delete-zero-size-repos.mjs --env-file=examples/.env --yes --force
```

Convert JSON output to CSV

If you saved JSON output from the examples you can convert it to CSV with the
included helper:

```bash
# from a file
node ./scripts/json-to-csv.mjs --input=stale.json --path=stale > stale.csv

# or via stdin
cat stale.json | node ./scripts/json-to-csv.mjs --path=stale > stale.csv
```
